# UPDATE gate

Use source+ticketKey identity and shared update paths. Review independently per target.

Verify:
1. Explicit source confirmation, complete original description and separate AC retrieval result. If only separate AC is empty/unavailable, accept empty-or-unavailable and inspect description; do not fail that alone.
2. Completed attachment-reader inventory, including explicit zero attachments; all imported readable files considered with relevance reasons, skipped files disclosed. Material unreadable evidence is resolved.
3. Original baseline obligations preserved unless explicit supported changes authorize otherwise; incremental requirements trace to Story/AC/FR/tests.
4. Manifest contains business preservation and attachment mapping, not scoring/audit fields.
5. attachmentAction=none: empty replacement mapping, no claimed new upload in Story, no selection required, local reviewed SPEC still exists.
6. attachmentAction=replace: returned existing IDs, explicit relevant selection, reviewed output path/name, supported business preservation. Ambiguous filename choices resolved before PASS. Multiple originals mapped to one output require explicit confirmation and preservation of all relevant obligations.
7. Distinct requested replacement contents have distinct current SPEC files. Review every state.specArtifacts entry and original-to-output preservation map. All headers, body/final bindings and selected attachment mappings must agree; a primary-file PASS cannot cover an unreviewed extra file.
8. Summary unchanged unless replacement is explicitly supplied or supported. No priority/assignee/labels/custom fields/status/link changes or implicit add/delete/create.
9. Imported source evidence remains unmodified; replacement is the reviewed output copy.
10. No known external baseline change remains unreconciled.

A resolved none action can have updateReady=true. Inherited broad ticket sizing is not alone a blocker or permission to create new tickets. If requested scope genuinely requires splitting, return the exact user decision needed. Every target gets its own result; one PASS cannot hide another target's blocker.
