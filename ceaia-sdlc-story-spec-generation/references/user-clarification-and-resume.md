# Clarify the actual blocker and resume

Generation owns user interaction; reviewer stays read-only. Use only when a material business fact/decision is missing, sources conflict or the bounded local repair policy stops. Missing Jira setup follows [first-entry assembly](jira-json-assembly.md): ask only missing facts, keep default Jira intent and do not open a preparation-only/Jira-backed route selector. Technical recovery stays in its owning step.

Never turn authentication into a business question: do not request staffId or make an absent staffId a setup/profile blocker. Authentication and user ownership come from trusted platform context; a live tool's unavailable required identity is WAITING_TOOL, not a prompt for an employee ID. On resume supersede only old pending staff-ID questions under the workflow contract, preserving all business questions and known outcomes.

1. Read the latest finding and affected saved item. In chat show its actual path, section/AC/TC/FR, a short quotation or precise absence, source-based reason, impact and required fact. Do not invent line numbers or ask the user to restate known requirements.
2. Ask only the missing fact through `ask_user_question`. Keep the popup to a unique short item locator, short reason and one concrete question; group shared decisions, preferably no more than three related questions. Full paths/details stay in chat. If the issue is an AI writing error with sufficient evidence after the repair limit, request a named finite additional batch instead of inventing a business question.
3. Save pending question IDs, finding IDs, affected artifact/item and evidenceRevision in state.userRecovery; store actual tool questionRef only if returned. Set WAITING_USER and yield for that candidate. If the popup capability is unavailable, return the precise question once in text and wait.
4. Bind the answer to the pending item and current evidence. Record a substantive new fact/decision in the matching version-bound Plan section of the existing internal preparation record; preserve original sources and previously used sections/reports. A repeated answer or resume alone creates no revision/file. Keep useful partial answers and ask only the unresolved fact. Do not regenerate after each partial answer.
5. A substantive new business decision starts the affected candidate's new evidenceRevision under the workflow contract. An extra-batch permission only extends that scoped limit; it does not reset counters. Dismissal, a new session or a vague continue is not a new fact or finite repair grant.
6. Once the answer is sufficient, update only affected canonical JSON/files, align dependent artifacts, independently re-review, synchronize SPEC before scoring and resume the final preview/path-only export stages. Do not ask another continue question. Unrelated current candidates stay valid.
