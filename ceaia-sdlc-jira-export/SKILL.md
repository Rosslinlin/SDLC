# CEAIA JSON Story Export

Version: 6.1.0-preview.10 — 2026-11-09. State contract: 7 (additive profile persistence state). Runtime: GPT-5.6 Luna or GPT-6 Luna. Execution: text-only.

Generation owns project/type/field discovery, configuration, JSON assembly, content repair, review and scoreUserStory. This skill consumes their current evidence, obtains the scored file's frontend upload confirmation and invokes the exporter with one path. Use existing platform capabilities; no scripts, new tools, business generation or scoring here.

SDLC never requests staffId from the user or adds it to new profiles, business files or export arguments. All generated files, including scored JSON/SPECs, previews, state and attempt records, belong to the current **session Workspace**. Use the authenticated **user Workspace only for ceaia-sdlc-jira/profiles.json** through the profile procedure, never as the destination or fallback for session artifacts. Supported Workspace tools or native file actions executable by this agent are sufficient; no extra identity/scope field or specially named persistence tool is required. A missing staffId does not invalidate a profile or block this path-only export.

For profile-only recovery after confirmed issue success, go directly to [profile closeout](references/workspace-profile.md) using retained results/configuration. Missing newer onboarding/state fields never sends that recovery back through questions, authoring, review, scoring or Jira submission.

## Fixed tool boundary

The only create or update export invocation is java-base-mcp.exportjirabydynamicfield with exactly one argument: story_json_workspace_path, copied from paths.storyJsonPath and the actual passing score input. For updates, issueIdOrKey is already inside the scored JSON after issueType; attachmentsJson is also inside that file. Neither is an extra tool argument. Do not pass business fields, identity values, attachment controls, batch arguments or a separate association payload beside the path. Backend association/queue work is required and must be evidenced, but there is no second five-field binding call in this JSON route.

Do not query projects/types/metadata, repeat normal Jira intake, render/partition Story text or rebuild the JSON during export. A defect or requested change returns to generation's assembly/review/scoring procedure. Test Case export, other issue types, generic helper/legacy routes and automatic fallback are outside this skill. Default multi-item execution is one confirmed file and one export call per candidate; failed/partial/unknown required outcomes stop subsequent Jira submissions after any eligible profile closeout.

The bundled workflow continues to this stage unless preparation-only/no-Jira or stopped. It must still obtain the current frontend content confirmation before writing. See [call examples](references/call-examples.md) for the one-argument shape; examples are not real paths or result schemas.
